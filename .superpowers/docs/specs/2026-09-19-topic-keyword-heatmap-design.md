# A topic × keyword relevance heatmap — Design

## The request

A second heatmap in the Keyword gap section, crossing *topic* with *keyword*, alongside the
category × keyword grid shipped in #264/#265.

## What "topic" resolves to, and what it cannot

"Topic" has no prior definition in this repository. The only `topic` in the codebase is Kafka
configuration (`topic_policy.py`). Four readings were put to the user; they chose **primary genre**,
the `l2` taxonomy level. The other three are recorded here because the reasoning outlives the choice:

- **Query as topic — rejected as circular.** `query_of(genres)` is `" ".join(genres)`. The query
  *is* the genre list, which is why `top_queries` reads `Documentary`, `Horror`, `Drama`. Crossing it
  with keyword would produce string containment, filled by construction, and reading it as relevance
  would repeat the error in [[project_grpo_position_feature_is_circular]].
- **Genre × decade (`l3`) — not available.** `release_year` is absent from this data, so `l3`
  evaluates to `Action·unknown`. The axis would collapse to plain genre.
- **A fitted topic model — out of proportion.** The only text these events carry is the movie title.
  Topics would be unnamed clusters that shift on every re-fit, so the axis would not be stable
  across snapshots.
- **Kafka topic — measurable but off-question.** It answers whether every genre survives each hop,
  a plumbing question. CTR is a property of the audience, not of the stream a row travelled through.

## Data

`compute_keyword` gains `topic_grid`, built exactly as `grid` was but grouping on `l2`:

| column | meaning |
|---|---|
| `topic` | the item's primary genre (`l2`) |
| `keyword` | a genre the item carries (rows exploded over `genres`) |
| `movie_impressions`, `query_clicks`, `ctr` | as in `grid` |

**No rank cap**, for the reason `grid` has none: a truncated row reads as "these are the only genres
served under this topic". Bounded at 18 × 18 = 324 cells.

This is consistent with the argument made in #264 rather than a reversal of it. That PR declined to
lift the cap globally because `l3` is ~180 × 18 ≈ 3240 rows. 324 rows is roughly 30KB of JSON, which
the snapshot can carry; 3240 is what it could not.

## The structural diagonal

An item whose primary genre is Action always carries Action. So every `(X, X)` cell is populated by
construction and is normally the highest-support cell in its row. That is an artifact of the
derivation, not a measurement, and an unmarked heatmap would invite reading the bright diagonal as a
finding.

The diagonal therefore renders with a visible outline and the legend names it. The cell keeps its
real value — it is not blanked, because the value is true; it is only labelled as forced.

## Rendering

`CategoryKeywordHeatmap` becomes one `RelevanceHeatmap` parameterised by the row field and its
label, used twice. Two real call sites justify the parameter; nothing else is generalised.

Both heatmaps keep the established treatment: heat is `ctr / max(ctr)` over the grid, zero-anchored;
a pair never served is hatched rather than pale; the ramp is capped at 70% of the accent so dark ink
holds 5.18:1 contrast.

**Known limitation, carried over and unchanged:** colour encodes rate without support, so CTR over
184 impressions is shaded like CTR over 919. The cell title carries the impression count. This was
flagged on #265 and is not addressed here.

## Snapshot

Regenerated by re-running **only the exporter** against the Parquet the last simulation left in
`/tmp/spark-recsys/movie-category-sim/training-samples`, with Redis still serving that run's movie
metadata. The snapshot then differs from master's by the new key alone, apart from the freshness ages
that shift with wall-clock ([[project_dashboard_snapshot_regeneration]]) — a far smaller and more
reviewable diff than the 1721-insertion churn a fresh simulation produced in #265.

## Acceptance

1. `compute_keyword(df)["topic_grid"]` crosses `l2` with exploded genres, uncapped.
2. The exporter ships it with no `.head()`; `tops` stays truncated.
3. The section renders two heatmaps; the topic one marks its diagonal.
4. A snapshot lacking `topic_grid` shows the re-export note, not an empty table.
5. The committed snapshot carries `topic_grid` and every other section's numbers are unchanged.
6. Full suite green; `validate:data` passes; build clean.
